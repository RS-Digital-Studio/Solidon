# Der festgeschriebene Versionssatz für Entwicklung und native Paketbauten.
#
# Warum es die Datei gibt: die Abhängigkeiten in `pyproject.toml` haben offene
# Untergrenzen, damit neue Versionen von selbst einziehen. Ohne einen festen
# Satz installiert jeder frische Klon etwas anderes als die Maschine, auf der
# es zuletzt grün war — genau das ist am 2026-08-06 passiert: ein Klon zog
# numpy 2.5, und sechzehn Tests fielen um, ohne dass eine Zeile Code sich
# geändert hatte.
#
# Constraints, nicht Requirements: die Datei sagt, *in welcher* Version ein
# Paket installiert wird, nicht *dass* es installiert wird. Der
# Windows-Eintrag (pywin32-ctypes) greift auf Linux deshalb einfach nicht.
#
# Die Pins gelten für jedes CPython 3.14, die CI baut mit 3.14.8.
# Der Paketbaum enthält pygfx;
# VTK, PyVista, PyVistaQt und deren Adapterabhängigkeiten entfallen (RM-050,
# 23.09.2026 — VTK war zuletzt nur noch die Geometriebibliothek der
# Bausteinbereichsprüfung, jetzt ``app.core.geom.mesh.ray_hits_batch``).
#
# Erneuern: Umgebung neu aufbauen, Suite grün fahren, dann
#   .venv\Scripts\python.exe tools/check_env.py --freeze
# Wann es lohnt, sagt der Job „Neueste Versionen" in build.yml, der ohne diese
# Datei frei auflöst. Er läuft bei öffentlichen v*-Tag-Pushes und bei
# Handstarts mit gesetztem check_latest im öffentlichen Repository.
